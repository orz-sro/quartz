#操作系统 为什么内存中  BIOS 主板 存储自举程序 用的是 ROM ，为什么不是 RAM？

>答：  程序是不能断电死亡的，所以对于 BIOS 来说必须用 可存储介质 ，例如磁盘或者光盘，但是 ROM（半导体存储介质）发展到今天已经出现了可擦除性的种类，当今电脑采用的 BIOS 存储器 就是 Flash Memory 或 EEPROM，一般说的刷机升级利用了其 可写性
 

回 顾 O S 的 引 导 过 程

- **ROM 登场：** 按下电源，CPU 通电，立刻读取 **ROM** 中的 BIOS 自举程序。BIOS 开始执行 POST（开机自检），检查你的显卡、内存、硬盘好不好使。
    
- **RAM 初始化：** 自检通过后，BIOS 会初始化电脑里的 **RAM**（内存条），让它进入准备就绪状态。
    
- **数据交接：** BIOS 去硬盘里找到操作系统（如 Windows/Linux）的引导文件，把操作系统的一部分核心代码从硬盘**加载到 RAM** 中。
    
- **RAM 掌管大权：** CPU 的控制权正式移交给 RAM 中的操作系统，BIOS 功成身退。

#操作系统 #计算机组成原理

虚存  或是  主存 这两个存储单位的划分 最终都是落到 块大小上的

1. 对于虚存 利用 页面 划分

2. 对于主存 利用 cache块 划分


两个存储概念的地址由:  （tag) #cache +  分块位数  +  offset位数  组合而来

因为 分块 + 块内偏移 本质上都是对存储单位的再划分，因此 地址 和原先的存储概念的 位数是一致的！！！

除此以外， offset 的 位数还和 系统的 编址方式相关联，假设 以字编址  此时 offset 的位数一定会减少，相对应的 分块位数 会增加

#操作系统 文件系统中的逻辑结构是怎么对应到实际存储的？

>逻辑结构到物理存储的映射，本质上就是“把用户视角的连续数据（无论是字节流还是记录流），按照物理磁盘块的大小进行裁剪、打包和对齐”的过程。
>
>- **流式文件**：直接按字节数硬生生切块。
  >  
>- **记录式文件**：考虑记录的完整性，决定是“跨块（Spanned）”切分还是“不跨块（Unspanned）”对齐，并依赖块内的辅助信息（如长度标记）来保持逻辑结构不丢失。
